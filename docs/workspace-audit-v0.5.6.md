# tunnelX 工作空间详细功能审计

日期：2026-10-03（北京时间）。基线：网站 v0.5.5、Windows 桌面 v0.5.0。修复版本：网站 v0.5.6、Windows 桌面 v0.5.1。传输协议继续为 H2。

## 1. 结论

主要购买、账号、节点、支付回调、计费、工单和网络传输具有真实实现。没有发现用固定成功响应或随机业务数据支撑主要页面的情况。但确实存在“数据保存了却没有入口”“字段可填写却不生效”“底层有实现但安装链遗漏”“操作记录太简略或归属不对”等问题，本次已针对复现项修补。

尚未实现的长期运营能力仍然存在，不能用本轮通过的测试代替这些功能。尤其是自动异地备份、主动支付查单、内层证书轮换、自动升级与大规模数据归档。第 5 节逐项列出。

## 2. 审计方法与覆盖

逐项核对“可见入口 → 请求 → 权限校验 → 事务/外部调用 → 返回结果 → 重启后结果”。同时核对配置字段的实际读取点、后台维护任务启动点、构建/安装/打包脚本和诊断命令。每项区分源码追踪、可复现缺陷、隔离动态测试、历史证据及本次线上验证。

四份分册包含完整功能矩阵和定位：

|范围|详细分册|重点|
|---|---|---|
|网站用户/管理/财务/客服|[网页逐项矩阵](audit-web-functions-v0.5.5.md)|登录、购买、退款、安全、节点、设置、统计、审计、每个操作入口|
|后台接口与运维|[后端逐项矩阵](audit-backend-functions-v0.5.5.md)|持久化、支付、权益、角色、邮件、配置消费、维护与备份|
|Windows 桌面|[桌面逐项矩阵](audit-desktop-functions-v0.5.5.md)|原生桥接、真实会话、DPAPI、代理恢复、连接、套餐、刷新、更新|
|传输/命令/部署/打包|[内核与发布矩阵](audit-core-deployment-v0.5.6.md)|H2、ECH、TCP/UDP、日志、安装器、备份脚本、构建与发布|

分册文件名中的 v0.5.5 表示审查起点，文内已标明本轮修复；不是要求回退到旧版本。第三方 vendor、自动生成 bindings、历史构建产物和私密部署配置没有逐行当作自有产品功能审查。

[本轮自有源码清单](workspace-source-inventory-v0.5.6.json)记录了 152 个文件的路径、大小和 SHA256，用于确定审查版本；文件入清单不等于每一行都获得形式化验证。

## 4. 后台审计现在具体记录什么

新记录保留旧字段 `time / actor / action / subject`，增加 `actor_name / subject_name / summary / changes`。变化项为 `field / label / before / after`，用明确允许名单生成，不把对象完整序列化进日志。

可以看到套餐价格、周期、额度、设备数、节点范围、启停状态，账号角色、封禁、验证状态，订单/付款状态、租约已用/预留，以及网站设置和支付方式变化。对象删除后仍保留删除前的可读名称。事务失败不会留下“成功修改”的审计；旧记录原样保留，界面说明旧版本没有字段差异，不虚构历史值。

密码、密码散列、节点 token、安装令牌、私钥、MFA 密钥、恢复码、商户密钥原文、CA/ECH 材料、邮件和工单正文不写入详细审计。网关/下载 URL 只显示协议与主机；公告和发布说明只记录有无与长度；密钥变更只记录配置状态/已更新。退款原因和对账自由文本不复制进审计，仍可在对应业务记录中查看。

目前不是防篡改审计平台：没有独立 WORM 存储、签名链、操作来源 IP/设备指纹、自动归档、按角色开放审计导出或失败登录事件中心。这里改善的是现有管理操作记录。

## 5. 尚未实现、仅有文件入口或依赖外部条件的能力

|能力|真实状态|现有替代方式/影响|
|---|---|---|
|真实支付宝/微信/USDT 结算|适配器与验签已实现，真实商户验收未完成|后台填写商户配置后，需要真实小额付款/退款核验；模拟支付不能代替|
|SMTP、告警收件人、政策、数据库、开售批准的网页配置|底层支持，尚无完整网页编辑入口|当前修改服务器私有配置；后台准备清单可看状态|
|网关密钥清除按钮|后端支持清除参数，网页主要提供保留/替换|属于缺操作入口，不是保存接口空壳；未擅自清除现有密钥|
|支付主动查单、自动账单对账|未实现|依赖已验证的回调和人工核实未知结果；不能声称自动补单|
|易支付/USDT 自动退款转账|未实现，当前流程明确为外部退款后登记|登记不会调用钱包转账；页面说明这一点|
|部分退款、优惠券、购物车、自动周期扣款、发票|未实现|当前按单个套餐创建订单、整笔退款、手动续费|
|邀请码列表/撤销|仅生成、单次使用、到期失效；无完整列表和撤销流程|不把生成邀请按钮视为完整邀请管理系统|
|内层叶证书与 origin CA 自动轮换|未实现|约六个月/一年有效期；需要提前人工更新和客户端信任迁移|
|自动异地备份/热备切换|未实现|同机小时加密备份已实现；本机下载的备份为人工离机副本|
|自动恢复演练/网页恢复向导|未实现|已有仅允许新库恢复的 CLI 及自动测试|
|运维高并发调度/独立外部监控|有限|节点探测和邮件任务存在串行处理；全服务停机需外部监控，90 秒是离线判定门槛|
|长期数据归档、业务上限管理|未完整实现|订单/工单有容量上限；审计、支付事件、挑战和租约无完整历史归档工作流|
|管理审计防篡改、失败事件中心|未实现|目前是事务内业务操作记录；见第 4 节|
|客户端自动更新、签名安装、自启动|未实现|提供 HTTPS 下载与 SHA256，用户手动更新；不会偷偷改启动项|
|桌面日志一键导出/网站集中日志检索|未实现|本地滚动日志和命令行分析可用；需要人工取文件|
|TUN、全局 DNS 接管、自动节点故障切换|未实现|当前显式 SOCKS/HTTP/系统代理；业务重连依赖应用和现有 H2 处理|
|Android APK、iPhone 客户端|未实现|当前只有 Windows 产品路径，用户此前未要求开始移动端开发|
|HTTP/3|已按用户要求移除|不属于待补功能；历史测试不代表当前仍支持|
|保证无 QoS/永久可用、浏览器 TLS 指纹仿真|不存在这类保证；指纹仿真未实现|不能从一次快速下载推断所有路径长期稳定|

这些是当前产品边界，未以“本次审计已修复”名义扩大成未经设计和验收的新系统。

## 6. 验证与上线证据

网站主站与测试站已经升级至 v0.5.6，Windows v0.5.1 ZIP 发布包已发布，公开下载与登记的 SHA256 一致。现有传输内核进程和用户正在使用的本地客户端没有被替换或重启。新桌面版本需要退出旧客户端后手动更新。

- 自有 Go 包完整串行回归 `go test -p=1 -tags=http2legacy ./... -count=1 -timeout=180s` 与 `go vet -tags=http2legacy ./...` 均通过。
- [新增网页功能回归](workspace-feature-dom-v0.5.6.json)：退款角色隔离、无效配置、详细审计、旧日志、探测显示和邮件入口。
- [用户旅程](buyer-journey-v0.5.6.json)、[管理员旅程](admin-journey-v0.5.6.json)、[基础后台](admin-dom-acceptance-v0.5.6.json)、[商业页面](admin-commerce-dom-v0.5.6.json)、[MFA](admin-mfa-dom-v0.5.6.json)：共 84 项网页操作检查。
- [桌面交互检查](audit-desktop-ui-v0.5.5.json)：6 项 DOM/受控桥接检查；真实会话、DPAPI、端口和隔离注册表另有 Go 测试。
- [原生 Windows 验收](admin-desktop-acceptance-v0.5.1.json)：真实 EXE，无 GUI 模式，严格 H2/ECH、8 MiB 校验下载、MFA、DPAPI、日志和代理保护。
- [服务器测试](admin-payments-gateway-v0.5.6.json)：42 个顶层测试函数通过，包括详细审计 PostgreSQL 落盘/重启、支付回调、备份恢复等。支付网关为模拟服务，没有真实扣款。
- [线上只读数据核查](live-data-workspace-audit-v0.5.6.json)：检查套餐/有效订单/权益的节点引用、重复发放和本轮真实发布操作的详细审计字段，仅保存汇总结果。
- [网站升级验证](admin-payment-deployment-v0.5.6.json)、[桌面下载发布](admin-client-release-v0.5.1.json)、[包完整性](admin-package-verification-v0.5.6.json)：以实际生成的 JSON 结果为准。

原生下载复测曾因旧的回环测试夹具已停止而失败。确认 18480 未监听后，只启动有时限的回环夹具完成复测，再停止夹具；没有修改正式节点访问限制或把环境错误当成客户端修复。

全量测试中还复现了 Windows 临时目录被短暂占用导致的清理失败；测试辅助函数在验证目录属于系统临时目录后，执行有界重试。最终全量测试通过。这是测试夹具清理修正，没有扩大正式程序的文件删除范围。

测试不等于证明所有代码无 bug。本轮没有 GUI 视觉验收、真实商户结算、多运营商长期压力测试或全新 Debian 独立主机安装验收。
