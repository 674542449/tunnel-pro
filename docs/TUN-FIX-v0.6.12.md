# TUN 出网故障修复记录（v0.6.12）

## 证据与原因

2026-10-03 本机旧版 TUN 会话 `9d2a44d1` 中，节点入口探测成功，DNS 有响应，部分 IPv4 业务连接正常；主动断开前出现 79 次目标 TCP 建连超时，主要目标为 Google 等站点的 IPv6 地址。节点存在 IPv6 默认路由，但从节点访问 Google 的 IPv6 HTTPS 连接在 5 秒内超时，同目标 IPv4 返回 HTTP 204。不能据此将故障归因于运营商 QoS。

旧版 TUN 向应用提供了 IPv6 通道，却没有验证节点实际 IPv6 出网能力，也没有处理 DNS 返回不可用 IPv6 的情况，导致应用长时间等待。

## 修改

- 每次连接 TUN 前，通过现有 H2 节点探测两个独立 IPv6 目标。不能确认均可达时使用 IPv4 策略；界面及 `tun_network_policy` 日志记录结果。
- TUN 捕获的 TCP/UDP DNS 统一通过 H2 内的 TCP 转发至公共解析器，设置并发上限、超时与备用解析器。解析失败返回 SERVFAIL 并记录 `tun_dns_failed`。
- IPv4 策略下对 AAAA、SVCB、HTTPS 查询返回无记录；继续捕获 IPv6，但立即拒绝其目标连接，促使支持回退的应用使用 IPv4。
- TUN 建立与清理 DNS 策略时刷新 Windows DNS 缓存。
- 安装包增加真实 TUN 验收门禁，报告必须与打包 EXE 的 SHA256 完全一致。

## 验收范围

`tun-product-acceptance-v0.6.12.json` 记录 11 项真实 EXE 验收：使用隔离测试账号及临时本地监听端口，以管理员权限启用完整 TUN 默认路由和系统 DNS 策略，不设置 HTTP/SOCKS 代理访问 Google 首页和 HTTPS 204 接口、下载 OVH 的 1 MiB 文件，验证 DNS 回答、IPv6 快速关闭、正常断开和再次连接。测试完成后确认本程序的网卡、路由、DNS 策略清空，原 Windows 系统代理值不变。

初次验收把虚拟网络栈完成本地 TCP 握手误当成远端 IPv6 成功，已改为检查数据流迅速关闭或重置。另一次 Cloudflare 测速下载返回 HTTP 403，改用节点直连已确认返回 HTTP 200 的 OVH 文件继续验收；没有将 HTTP 403 计为成功。Google 访问在该次测试中已成功。

另执行 Go 全量测试及 vet、桌面模块测试及 vet、UI 交互和 Wails 运行时回归。常规真实 EXE 验收报告另存于 `admin-desktop-acceptance-v0.6.12.json`。未启动界面做视觉测试。

## 限制

这次验证覆盖当前电脑与测试节点。没有验证所有 Windows 网络配置、其他 VPN 共存、企业私有 DNS，或进行长时间稳定性与吞吐量评估。公共解析器替换可能影响私有域名；IPv4 策略过滤 HTTPS/SVCB 记录也会禁用相应优化。应用自带加密 DNS 不会被改写，其 IPv6 连接仍会快速失败，但应用是否回退取决于自身实现。节点至公共解析器使用普通 TCP DNS，不是 DoH。

后台与客户端产品版本统一升级；原节点服务端核心与加密方案保持原样。已运行的旧客户端不会被替换，需完整解压新版并退出旧版后启动。
