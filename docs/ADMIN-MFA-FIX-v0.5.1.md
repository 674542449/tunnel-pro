# 管理后台二次验证修复 v0.5.1

此次更新只涉及管理服务及其网页，Windows 客户端继续使用 v0.5.0，节点内核和现有连接不需要更新。

## 使用方法

打开 https://test.xiaguamail.com/control/#security 并登录。

首次开启时，点击「开启二次验证」，输入当前账号密码。接着在验证器中手动添加页面显示的账号和密钥，输入验证器生成的 6 位验证码。确认成功后，妥善保存只显示一次的 10 个恢复码，关闭弹窗，再点击「返回管理后台」。

已有二次验证的账号，在登录表单填写密码及验证码或未使用的恢复码。未通过验证的管理会话会引导回账号安全，不能直接访问管理数据。

## 修复内容

- 为登录页、二次验证拦截提示和地址片段 `#security` 增加可直接进入的安全设置入口。
- 在强制二次验证期间，将管理菜单导航引导回可访问的设置页面。
- 将基础页面和安全功能合并为同一个实际加载的脚本，解决返回用户会话恢复早于第二个脚本加载时的空白页。旧版问题已通过真实 HTTP 资源与分开执行脚本复现。
- 修复输入密码后无法打开绑定验证器窗口的问题：连续弹窗在保存结束后继续执行。
- 服务端继续执行二次验证策略，403 响应提供结构化状态和安全设置地址。
- 侧栏支持滚动，入口不再因菜单过长而难以找到。

## 验收

使用真实本地管理 API 和实际嵌入网页资源，以 `require_admin_mfa=true` 验证返回会话、全部菜单、密码与 TOTP 绑定、恢复码、绑定后的全部管理页面、旧会话撤销及恢复码不可重放。没有使用图形浏览器或视觉渲染。

对应报告：`admin-mfa-dom-v0.5.1.json`、`admin-dom-acceptance-v0.5.1.json`、`admin-commerce-dom-v0.5.1.json`。部署后的主站和试运营站检查见 `admin-mfa-deployment-v0.5.1.json`。

验收不替生产所有者绑定验证器，也不重置所有者密码。生产账号的绑定由账号持有人按上述入口完成。
