# tunnelX Windows v0.6.13

完整解压安装包，再运行 `tunnelx-desktop.exe`。不要单独移动 EXE：TUN 依赖旁边的 `runtime` 目录。Windows 需要 WebView2 Runtime。

## 三种代理模式

- **绕过大陆**：国内域名、大陆 IPv4/IPv6 和局域网直连，其余流量经现有 HTTP/2 节点。遵循系统代理的应用自动使用；其他应用需手动设置本地 SOCKS/HTTP 代理。连接偏好中的系统代理需开启。
- **全局代理**：进入本机 HTTP/SOCKS 代理的流量统一经节点。不遵循 Windows 系统代理的应用不会自动被此模式接管。
- **TUN 模式**：退出客户端后右键“以管理员身份运行”。通过 Wintun 虚拟网卡接管 TCP/UDP，再转给本机 SOCKS 和现有 H2 内核。节点、管理服务 IP 保留直连出口；局域网沿用更具体的原有路由。ICMP 等非 TCP/UDP 协议不在接管范围，不能用 ping 成败判断代理是否可用。

连接期间不能切换模式，请先断开。旧版偏好升级后保留全局行为，不会擅自切换分流。

## 国内分流规则

来源：[Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) 与 [gaoyifan/china-operator-ip](https://github.com/gaoyifan/china-operator-ip)。内置快照固定上游提交并附 SHA256；设置页可更新，失败保留旧规则，下次连接生效。

匹配顺序：局域网、直连例外、国内域名/IP、已知代理域名；未知域名最多等待本地 DNS 500 ms，所有解析结果均为大陆公网 IP 才直连，否则代理。精确域名与域名后缀分开处理。直连例外支持域名、IP、CIDR，最多 256 条，仅影响绕过大陆模式。

规则不是永久完整清单，企业新增域名、境外业务和第三方 CDN 可能需要更新或补例外。直连流量不经过节点，因此不会产生节点端的套餐流量计费；本机速度图会包含经过本机代理处理的直连字节。

## TUN 恢复与依赖

正常断开恢复本程序创建的路由、DNS 策略。客户端意外退出时独立守护进程通过标准输入关闭检测并清理；未完成的操作保存恢复记录，下次以管理员权限启动可在设置中“恢复网络与代理设置”。不应手动删除状态记录来代替网络恢复。

TUN 适配层采用 [tun2socks](https://github.com/xjasonlyu/tun2socks) 和 [Wintun](https://www.wintun.net/)，并非自行发明的 IP 网络栈；现有 H2 传输和加密不变。安装包附上游源码快照、许可证、Go 依赖声明及签名原版 Wintun DLL。重建见 `tools/build-tun-runtime.py`，重建后需要重新构建和验收客户端。

v0.6.13 已使用本安装包的真实 EXE，以隔离测试账号启用完整 TUN 默认路由和系统 DNS 策略，验证 Google 首页、HTTPS 检查接口、1 MiB HTTPS 下载、IPv4 DNS 回答、不可用 IPv6 快速失败、断开重连以及网卡/路由/DNS 清理。报告位于安装包 `acceptance/tun.json`；这是当前电脑与测试节点的实测，不代表所有 Windows 网络环境或其他 VPN 共存情况均已验证。界面没有启动或进行视觉验收。

后台与本安装包使用同一产品版本 v0.6.13。更新不会自动替换已运行的旧客户端，请退出后再启动新版。

## v0.6.13 自动恢复与网络检查

启用 TUN 前，通过节点探测两个 IPv6 目标；不能确认可用时使用 IPv4 模式。连接期间约每 30 秒复检，失败禁用 IPv6，连续两次成功后恢复，并刷新系统 DNS 缓存。保留 IPv6 捕获路由，防止 IPv6 绕过隧道；对于缓存或应用自带 DNS 得到的 IPv6 地址，立即返回连接失败，让支持回退的应用改用 IPv4。

TUN 捕获的 TCP/UDP 53 端口查询通过 H2 内的 TCP DNS 转发至 1.1.1.1、8.8.8.8；不可用时回退同两家服务的 HTTPS DNS。优先使用最近成功的通道，各通道最多等待 2 秒，整体最多 8 秒，并限制并发。HTTPS DNS 使用固定引导 IP，验证服务域名与证书，不依赖故障中的系统 DNS。IPv4 模式下对 AAAA、SVCB、HTTPS 查询返回无记录响应，避免不可用的 IPv6 地址及 IPv6 hints；这可能同时关闭依赖 HTTPS 记录的站点优化。客户端自身 H2/ECH 配置不变。TUN 启动与清理 DNS 策略后刷新 Windows DNS 缓存，断开后删除本程序的 DNS 策略。

应用自行缓存的 DNS 或自带加密 DNS 不会被改写，但其 IPv6 连接仍受 TUN 的快速失败策略控制。所有解析都经现有加密 H2 隧道。普通 TCP DNS 模式下，节点至公共解析器的查询不加密；DoH 模式还会对这段查询进行 HTTPS 加密。


连接后分别检查节点入口 TLS/ECH、DNS 的有效 IPv4 回答、独立于 DNS 的 HTTPS 出网。首次检查立即执行，后续约每 30 秒检查一次；首页和诊断页分别显示结果。测试目标有限，不代表所有站点可达。DNS 和 HTTPS 检查也适用于绕过大陆、全局模式，检查流量始终经节点。

TUN 守护进程约每 3 秒检查默认出口路由、网卡和地址，连续两次变化后清理旧 TUN，由客户端重新获取配置并创建路由。检测到超过 15 秒的运行间隔也触发恢复。重试间隔逐步增长到 30 秒，可随时取消；主动断开、退出或注销会停止重试，旧会话的通知不能覆盖新连接。

重建会中断既有 TCP/UDP 会话，应用需要自行重试。清理和重建期间 Windows 恢复原路由；本版没有断网保护（kill switch）。电脑短于 15 秒的休眠且出口未变，不会仅因时间间隔触发重建。当前验收通过暂停测试守护进程模拟恢复、在隔离网段注入路由指纹变化；未实际切换物理 Wi-Fi 或让整机休眠。
