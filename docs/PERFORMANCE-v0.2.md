# tunnelX v0.2 性能修复与复测

测试日期：2026-10-01，Windows amd64 → `146.56.99.255:8443`。用户反馈 fast.com 为 **5 MB/s，约 40 Mbps**；当前没有连接同服务器的其他协议可供对照。

结束时只读检查发现 Windows 系统代理已启用，但指向 `127.0.0.1:7890`，该端口由 `xray` 进程监听；tunnelX 的 HTTP 代理监听 `127.0.0.1:8088`。因此无法确认用户此前的 FAST 页面测量实际经过 tunnelX。本报告中的下载与 Netflix 样本均明确连接 tunnelX 本地代理端口，不依赖系统代理。重测 FAST 页面时，应在 tunnelX 面板启用系统代理；程序会保存当前设置，退出时恢复。本次没有更改该系统代理设置或停止 xray。

已复现旧客户端 H3 下载偏慢，并验证 H2 可恢复吞吐。v0.2 自动模式改为 TCP 优先 H2、UDP 优先 H3，保留相同隐私配置的双向故障回退。TLS、ECH、鉴权和线上帧格式保持原样。服务端无需升级或重启。

## 同源下载证据

使用测试域名公开 HTTPS 临时文件，文件为 64 MiB（67,108,864 字节），SHA256 为 `f8dfeaaa09d17ea0e07bcd70bdbf38d55406a6099c6a263a0a27e8e313f12067`。每次独立应用 HTTPS 连接，严格验证目标证书，完整文件校验通过。速度是字节数除以完整请求耗时，包含连接和首字节等待；MB/s 按十进制计算，Mbps = MB/s × 8。

|---|---|---|---|
| 用户正在运行的 v0.1，auto 实际选择 H3 | 3.36、4.23 | 26.88、33.84 | [旧 H3](performance-running-client-h3.json) |
| 同一个运行中的客户端，切为 H2 | 22.73、28.58 | 181.83、228.63 | [H2 切换后](performance-running-client.json) |
| 独立新建的 H3 测试连接 | 16.61、18.52 | 132.88、148.12 | [独立通道对比](performance-investigation-20261001.json) |

| 新版 Windows EXE，默认 auto | 21.63、30.73、20.24 | 173.07、245.82、161.90 | [新版实际程序](performance-client-v0.2.json) |

新版三次下载每次增加一个 H2 流、零个 H3 流，与默认策略一致。独立直连样本为 20.56 MB/s；各组测试顺序执行，已有应用流量和线路变化可能影响数值，不能将单次峰值作为固定速率保证。临时文件在测试后撤下。

旧版自动模式只在连接或建立请求失败时回退。H3 已建立却吞吐下降时，后续下载仍复用同一条 H3 连接。新建 H3 与正在运行的旧 H3 的速度不同，说明连接状态或复用条件可能有关；尚未确认是拥塞状态、丢包、并发流量还是实现问题，也没有证据判定运营商 QoS。本次修复通过调整 TCP 默认通道绕开已复现的慢路径。

服务器原先已启用 TCP BBR 和 fq；本次没有修改 sysctl、替换 QUIC 拥塞算法或放宽证书校验。H2 通过系统 TCP 使用 BBR，H3 继续使用 CUBIC。传输策略更适合本次观测到的线路，但不保证所有线路上 H2 均更快。

## 正确性与回退验收

- `tools/build.ps1 -ClientOnly`：全套 Go 测试与 vet 通过，Windows 程序构建成功。
- `go test -race -tags=http2legacy ./... -count=1 -timeout 120s`：通过。
- [线上 16 项验收](acceptance-client-v0.2.json)：全部通过，包括普通 / 严格模式 H2、H3，私网目标拒绝、错误 Token 拒绝、证书错误与 ECH 拒绝禁止回退，以及 TCP 被阻断时回退 H3。
- [新版实际 EXE 自动分流](acceptance-auto-client-v0.2.json)：HTTPS CONNECT 使用 H2，SOCKS5 UDP DNS 请求使用 H3，目标域名解析成功，两条通道严格 ECH 成功。测试使用独立端口，未启用系统代理。
- 本地集成测试覆盖 H2 / H3 响应头停滞回退、TCP 数据与半关闭、UDP 业务、双隐私模式；回退发生在业务数据写入前。

修改模式只作用于新请求，现有连接不迁移。用户正在运行的旧版已设置为 H2，旧配置保存为 H2；新版配置为 auto 并明确设置 TCP 首选 H2。升级时从旧版控制面板退出，再启动新版即可。

测试后已退出独立测试客户端、移除服务端临时下载文件和临时 FAST 签名地址，按 SHA256 校验恢复原 Caddy 配置并 reload；生产 tunnelX 服务没有重启，证书定时器继续运行。[清理和服务状态证据](performance-cleanup-v0.2.json)。

本次未完成长时间弱网复测、多运营商对照、真实播放器卡顿率或 FAST 浏览器显示值验收。图形界面没有重新进行浏览器视觉验收；新增状态字段与控制接口通过程序请求验证。无法保证不会被识别、封 IP 或运营商 QoS。
