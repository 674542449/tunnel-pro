# tunnelX v0.2.1 规范补充

线上鉴权、`Tunnelx-Version: 1`、CONNECT / UDP 帧格式、TLS 套件和 ECH 不变，继续遵循 [v0.1](PROTOCOL-v0.1.md) 和 [v0.2](PROTOCOL-v0.2.md)。服务端升级与现有客户端兼容；以下新增配置只有 v0.2.1 服务端认识。

## 源站地址排序

服务端配置新增可选字段：

```json
{
  "preferred_target_ips": {
    "tempdelivery.13376767.xyz": ["104.21.35.213"]
  }
}
```

最多 128 个完整域名，每个域名 1–8 个公网 IP 字面量。域名键要求小写、无末尾点，不支持通配符。上述 IP 是本次节点实测选择，其他部署应先测量自己的出口。

目标请求仍先鉴权，再使用服务端 DNS 和原有目标地址限制。匹配时将请求域名转为小写并去掉末尾点；只调整已通过地址检查的当前 DNS 结果顺序。配置中的地址不在此次解析结果中时不使用，不为该域名增加地址，不改变其他域名的顺序。多个首选地址按配置顺序排列，其他地址保留原顺序。TCP 连接建立失败继续尝试剩余地址，UDP 选取排序后的首个地址。

这是基于部署者测量的可选排序策略，未实现地址自动测速、持续吞吐监控或已经建立业务流的迁移。能够成功连接但随后吞吐较低的地址仍不会被自动替换。目标 TLS 由应用正常验证，所有代理流量继续经过服务器。

## 检测连接隔离

`PublicGET` 为每次检测创建独立客户端 Mux，复制调用时的传输模式、隐私模式、固定服务器 IP、CA 和 ECH 配置。响应关闭或检测失败时关闭该检测的通道，业务 H2 / H3 连接继续使用自身 Mux。检测结果更新状态中的 TLS / ECH 信息与回退计数，不计入业务流数。调用方必须关闭响应 Body。

普通和严格模式均使用同一隔离方式。检测不会改变调用方的模式，也不会在 ECH 拒绝或证书错误时放宽隐私要求。

## Windows 启动顺序

成功读取配置并创建 Mux 后，先绑定 SOCKS、HTTP 和控制接口三个端口，全部成功后才恢复同目录保存的崩溃代理备份。绑定失败时提供端口和退出旧版的提示并结束新进程。这样在重复启动失败时不读取或恢复正在运行副本的代理备份。显式 `-restore-proxy` 仍按照用户请求直接恢复备份。

此行为没有实现跨不同端口配置的进程互斥。多个副本应使用不同可写目录和不同端口；日常使用应先退出旧版再升级。
