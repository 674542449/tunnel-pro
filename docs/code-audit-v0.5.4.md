# v0.5.4 功能补齐与缺陷修复

本轮检查自有 Go 包、网站前端和 Windows 桌面入口，重点核查支付、权益、权限、节点管理、数据库与恢复流程。第三方 vendor 和生成代码没有逐行人工审计。

## 补齐的功能

- 支付宝、微信 SVG：用于支付配置列表、配置表单、付款选项和付款记录；与三个 USDT 网络图标共同打包为本地 SVG。
- 用户管理中的角色编辑：可分配用户、客服、财务和管理员；修改后撤销该账号既有会话，禁止修改自己的角色。
- 套餐节点范围编辑：可选全部或指定节点，保存和重开表单均保留选择。指定范围不能为空，接口拒绝不存在或重复的节点 ID。
- 一键添加节点时可选择测试范围，并显示节点实际范围；模拟付款模式仍由后端强制隔离。

## 修复的缺陷

- 流量加购缺少前置条件检查：创建订单、首次创建收银台时验证当前套餐及节点范围，避免无法使用的加购订单进入付款。
- 套餐在付款到账前到期：以前真实到账通知会因无法发放权益而失败。现在保留付款、设置订单为「已付款待处理」、记录告警，并允许退款；不会虚构权益或重复开通。
- USDT 下单响应丢失后收到有效回调：结清下单状态并自动解决「下单待核实」告警，维护任务不再将已付款订单标记为下单未知。
- 财务和客服账号可通过接口关闭强制 MFA：后端统一执行工作账号的 MFA 要求。
- 美元和欧元套餐、订单被统一标为「元」：现按实际币种显示；流量加购显示当前周期及沿用的设备限制。
- 退出登录或密码重置后公共套餐目录不恢复：会话清理后重新加载访客目录。
- DOM 验收退出时仍有未结束请求：测试等待请求完成后关闭页面，避免误报异步异常。
