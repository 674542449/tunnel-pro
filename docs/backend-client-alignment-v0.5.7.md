# 后台、Windows 客户端与节点内核对齐检查

日期：2026-10-03（北京时间）。管理后台升级至 v0.5.7，Windows 客户端升级至 v0.6.3。现有节点传输内核未替换。

## 本次发现并修复

|不一致|原来的影响|修复|
|---|---|---|
|节点列表不返回账号对该节点的权限|客户端只依据账号总览的 `active`，套餐限制节点、测试/正式权益混合时可能错误允许或阻止连接；网页也显示最终会被拒绝的配置下载入口|节点列表新增 `access`，由与配置导出和节点同步相同的 `accountForNode` 计算。客户端按选中节点权限控制连接和探测，并显示原因；网页用户端隐藏无权下载的配置入口|
|套餐节点范围没有完整传到购买确认|后台支持指定节点，客户端展示金额、流量、设备数，却不展示范围；同价同额度但范围变化时也不要求重确认|网页套餐列表显示范围；客户端套餐卡和确认页显示节点范围；订单内容比较包含排序后的节点 ID，变更后要求再次确认|
|人工订单被上一版客户端错误关闭|后台非商业模式支持创建订单、管理员人工核实开通，v0.6.2 却把 `commercial.enabled=false` 当成不允许购买|恢复人工订单创建与继续处理，明确显示“管理员核实开通”，不会宣称在线支付或自动扣款。v0.6.2 审计中对此流程的判断不完整，以本报告更正|
|发布版本格式不一致|后台接受预发布版本，客户端只比较普通三段版本，合法的 `-rc` 发布不能正常提供更新|统一支持预发布标签及构建信息；同一基础版本正式版高于预发布版，构建信息不触发升级|
|邮箱验证在旧授权路径上检查不同|配置导出拒绝未验证账号，但旧手工授权路径可能仍下发节点授权|节点同步和租约校验补上邮箱验证条件，与配置导出规则一致；管理员无需重置账号或凭据|
|后台变化依赖客户端手动刷新|成功加载后只轮询本机连接状态，后台退款或停用可能长期未反映在客户端列表|每 60 秒后台刷新账号、节点、套餐、订单和公开服务信息；保留焦点恢复/手动刷新和故障退避。网络失败时不承诺在 60 秒内更新|
|网页仍可能显示商业模式旧试用入口|网页旧入口只检查试用时长，接口却拒绝商业模式旧试用|网页与客户端均按服务模式显示；非商业模式仍保留有效试用|

## 功能对照

|后台功能|客户端行为|节点/服务端执行|结果|
|---|---|---|---|
|账号注册、邀请、邮箱验证、MFA|调用同一登录/注册 API，展示邀请码及二次验证；密码找回转网站|后台统一校验；本机凭据使用 DPAPI|接口一致；账号安全管理留在网站|
|节点添加、安装、启停、删除|读取已启用且完成安装的节点；区分在线状态与账号权限|节点配置强制 H2/strict；停用后停止授权下发|已对齐，不会把心跳在线等同于账号有权使用|
|套餐指定节点、测试/正式范围|显示套餐范围，按节点级权限决定能否连接|配置导出、授权同步和计费租约使用节点范围|已修复主要错位|
|续费、额度、到期、退款|展示账户总览，周期同步当前权益；选中节点权限单独计算|服务端最终授权与扣量，退款撤销相应权益|通过购买/退款合同测试；客户端缓存不替代服务端校验|
|设备数和流量限制|展示套餐设备上限与账户额度|计费节点通过租约约束并发设备和额度|核心执行机制保留；不在客户端重复实现账本|
|在线支付与人工订单|创建/复用订单，确认内容，转网站完成付款或人工核实|网站处理易支付、USDT 等支付通知、对账和退款|已对齐；客户端不内嵌支付网关密钥或退款管理|
|公告与客户端发布|读取公开公告/发布信息，手动下载更新|后台校验 HTTPS 链接、SHA256 和版本格式|已修复预发布版本比较|
|工单、审计、告警、角色管理|通过网站入口访问用户可用功能|管理员、客服、财务分别由后台权限控制|这些是网站职责，不要求桌面端复制后台管理页面|

## 验证证据

1. 新增跨接口测试：购买指定节点套餐后，节点列表权限、配置导出和节点授权同步一致；未覆盖节点仍拒绝；退款后列表、配置和授权同步同时拒绝。
2. 对未验证邮箱、账号停用、套餐未覆盖及到期分别检查节点级权限；增加旧授权邮箱验证回归。
3. 发布版本格式的服务端校验，与客户端预发布/正式版/构建信息比较分别回归。
4. Go 全量测试及 vet 通过；新增合同测试 race 检查通过；原生外壳测试通过。
5. 真实隔离管理服务的网页回归：23 项管理界面、14 项购买者旅程、9 项管理员旅程通过。
6. Windows 客户端：47 项界面交互、8 项实际 Wails 生产运行时脚本回归；发布 EXE 验收记录见 `admin-desktop-acceptance-v0.6.3.json`，包含升级后节点级权限数据、实际登录和三种代理下载。
7. 主站、测试站已部署 v0.5.7；线上测试账号的节点权限、配置导出及账户接口验证通过。配置、支付设置、节点安装产物和原节点进程保持不变；部署前后保存加密备份并保留旧二进制供回滚。

对应机器记录：`admin-alignment-deployment-v0.5.7.json`、`desktop-product-ui-v0.6.3.json`、`desktop-runtime-startup-regression.json`、`admin-desktop-acceptance-v0.6.3.json`、`admin-client-release-v0.6.3.json`。

## 验证边界与更新方式

网页与客户端界面采用 DOM/运行时脚本自动化，Windows EXE 采用无窗口验收。未进行真实窗口、托盘点击、真实商户扣款或长期运营商网络测试。节点权限变化由后台最终执行，客户端列表刷新和节点授权同步各有周期，不是即时推送。

后台已经部署；Windows 用户需从托盘退出旧客户端，解压 v0.6.3 运行，才能看到节点级权限和新增的购买范围提示。旧客户端仍可调用原有 API，新字段属于向后兼容的扩展。
