# tunnelX v0.5.0：商业试运营基础

主后台：https://test.xiaguamail.com/control/ 。当前已升级，但只开放获邀的模拟购买，不实际收费。管理员首次进入会转到「账号安全」，需要自行绑定验证器并保存恢复码。

Windows 客户端新增验证码、恢复码、注册邀请码输入，以及购买与账号安全入口。现有 H2 数据传输方式和加密保持兼容。原始 8443 节点继续运行原 v0.4.0 内核；新安装的 v0.5.0 节点使用强制托管授权，清空静态令牌。

Windows 安装包：[tunnelX v0.5.0](https://test.xiaguamail.com/downloads/tunnelX-desktop-windows-x64-v0.5.0.zip)。网站登录页和账号首页提供下载入口及 SHA256，桌面更新页使用相同发布信息。该文件只含程序、默认管理地址、说明与许可，不含账号或节点凭据。

## 已实现

- PostgreSQL 事务存储：账号、节点、订单、付款、退款、权益、会话、审计、工单与告警独立保存为实体行；数据库唯一约束防止重复支付事件、重复订单权益和重复退款。通过行锁串行提交并发修改。迁移保留原账号密码散列、节点和额度；数据库迁移后禁止重新导入过时 JSON。
- 计费：创建订单时保存套餐快照。周期套餐按连续天数排队续费，每个周期单独计量；剩余流量不结转。流量加购沿用当前周期到期时间。本版只支持整笔退款，成功后撤销对应权益并重新排列后续续费周期。旧有人工授权保留兼容，但商业模式关闭旧的人工核销和无理由续期接口。
- 支付：模拟付款仅对管理员和获邀账号开放，只授予测试节点权限。Stripe Checkout 适配器按服务端金额生成收银台，用幂等键避免重复创建付款和退款；只有验证原始请求体签名的回调能够确认真实付款。重定向页面不发放权益。延迟到达的有效实付通知会入账并记录对账告警，避免用户已付钱却丢失权益。
- 账号安全：PBKDF2-SHA256 密码散列、请求限流、Secure/HttpOnly/SameSite Cookie、CSRF、防跨域、邮箱验证、单次找回链接、密码更新后撤销会话与节点凭据、TOTP 防重放、单次恢复码、管理员/财务/客服角色。邮件正文与验证器密钥使用独立用途的 AES-256-GCM 加密保存。管理站点 Cookie 按 URL 路径隔离。
- 节点额度：新计费节点从后台申请短期额度预留，多个节点共享设备限额与可用字节；数据在转发前计量，最后一次 TCP 读取会按剩余字节裁剪。预留最长 20 秒，常规同步约 5 秒；后台不可达时授权到期停止。退款对数据库立即生效，连接撤销受同步及租约有效期影响。
- 故障对账：节点异常退出后，未报告完的预留不会自动释放，也不会把未知字节当作实际使用计费。后台提示待对账，管理员核实最终计数后释放未使用部分。仍有效的租约禁止手动对账。正常停机提交最终计数。统计为服务器处理的隧道业务字节，并不等同文件大小、终端接收字节或运营商出口账单。
- 运维：每 15 秒维护订单及心跳告警，每 5 分钟检查节点 TLS、ECH 与 H2。心跳超过 90 秒没有更新会告警，恢复后保留时间线。SMTP 支持经验证的 STARTTLS/465 TLS、加密发件队列及重试；配置告警邮箱后投递异常及恢复通知。数据库异常使健康接口返回 503，外部监控可据此报警。
- 售后：用户工单、客服回复、关闭、权限隔离；工单内容作为文本显示。财务只读工单，客服不能退款或修改节点。
- 恢复：每小时生成 AES-256-GCM 加密备份，保留最近 336 份；已私下下载一份到本机。恢复命令只允许写入新文件路径和空数据库结构，不能覆盖运行中的数据库。配置里的安全密钥与备份加密密钥必须另行保留。

## 正式收款目前关闭

当前没有提供真实支付商户密钥、回调密钥、SMTP 账号和运维告警邮箱。正式服务、隐私及退款政策仍为试运营说明，需经营方确认正式内容。管理员需亲自绑定验证器；现有老节点不是计费节点，正式购买应使用新建的正式计费节点。

「运维告警」列出开售准备检查。实际商户、邮件、管理员 MFA、正式计费节点、政策、近期加密备份及经营方开售确认全部满足后，才允许正式收银台。`live_approved` 默认关闭；配置检查不代替真实商户资格、邮件投递或真实扣款验收。

本版实现 Stripe 适配器，未接入微信支付或支付宝，也没有执行真实扣款、真实渠道退款、发票和税务处理。需要按实际经营主体选择可用的收款渠道。建议首批限制在 10～20 个获邀账号，先完成真实渠道测试，再逐步扩大。

## 验收范围

报告均在本目录，以 `admin-*-v0.5.0.*` 命名。覆盖重复付款通知、伪造/过期签名、金额不匹配、整笔退款及重复退款、续费周期、额度耗尽、跨节点设备与流量预留、重放验证码、密码找回、工单权限、节点掉线及恢复、后台重启、加密备份防篡改和空库恢复。

Windows 经独立 18447 测试节点执行 48 次 8 MiB 下载，384 MiB 全部通过数据完整性检查和严格 ECH。实际记录约 470 秒，测试进程含末次采样间隔运行约 8 分钟；吞吐数值包含握手和探测，不能代表 fast.com 或所有运营商路径，也不能证明永久可用。软件会继续记录定期节点探测。

最终计费内核另经强制 KILL 验收：正在使用的连接中断后，测试节点自动重启并恢复 H2/ECH 下载。64 MiB 尚未报告完的预留保持锁定，后台记录待核实告警；未知字节没有自动扣费或重新发放。该预留只存在于独立测试后台，留作故障对账样本。

Ubuntu ARM64 完成实际部署、PostgreSQL 和服务重启验收。Debian 13 ARM64 在 chroot 中执行同一后台及 H2 测试，未验证独立 Debian 主机的 systemd。网页交互使用 jsdom 与真实 API 验证，未打开浏览器渲染。Windows 最终原生可执行文件经无窗口模式验证：登录、严格 H2/ECH 节点连接、8 MiB 实际下载、DPAPI 状态、管理员恢复码及防重放、日志均通过；原系统代理保持原值，未修改用户正在运行的客户端。

## 部署与恢复

`tools/build-control.ps1 -Version v0.5.0` 构建 Windows 管理服务、Linux ARM64/AMD64 管理服务及配套计费内核。`tools/build-desktop.ps1 -Version v0.5.0` 构建 Windows 桌面客户端。依赖仍为 H2，保留 [H2 依赖补丁](../THIRD_PARTY_PATCHES.md)。

私密配置扩展为 `database_url`、`commercial`、`mail`，不要把这些实际配置提交或分发。PostgreSQL 在测试服务器只监听回环地址。公网节点仍通过 Ubuntu/Debian 一键安装命令接入；测试支付模式下新建节点自动标记为测试节点。

备份服务为 `tunnelx-control-backup.timer`，文件位于 `/var/backups/tunnelx-control/*.txbk`，密钥 `/etc/tunnelx-control/backup.key`，配置 `/etc/tunnelx-control/control.json`。保留这些文件时应使用私密存储；数据库导出的明文快照含令牌，不可公开。

```sh
# 对新建空库、新数据文件使用私密配置，保留原安全密钥。
tunnelx-control -config /private/new-control.json \
  -restore-new /private/snapshot.txbk -backup-key /private/backup.key
```

原始节点不会自动转换成商业计费节点。升级后的新节点无法使用安装时生成的静态客户端令牌，应登录管理账号获取配置。公开证书由 Caddy 自动维护；本版的内层证书仍有明确有效期（默认约 6 个月，origin CA 约 1 年），需要提前规划证书更新与客户端信任迁移。这个限制在长周期正式运营前应完成自动轮换，不应承诺永久免维护。

需要继续完善的规模化能力包括：正式收款渠道及对账、邮件投递与独立外部监控、代码签名与更新发布、内层证书轮换、跨主机容灾、数据库及审计数据归档、发票和正式客户政策。当前完成的是可验收的试运营基础，不是已经开售的付费服务。
