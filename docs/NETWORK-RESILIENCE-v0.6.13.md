# 网络恢复与分层检查验收（v0.6.13）

## 实现

TUN 运行期间每约 3 秒读取 Windows 默认出口路由、网卡状态和有效 IP 地址，连续两次变化后清理本程序的旧网卡、路由与 DNS 策略。守护进程出现超过 15 秒的运行间隔也触发恢复，覆盖长时间暂停/唤醒后的重建路径。客户端重新读取线路配置，再创建隧道与直连例外路由；失败时以 2、4、6 秒逐步退避，最大 30 秒。

自动恢复使用独立取消上下文和会话代次。取消、断开、退出、注销及登录失效都会撤销恢复，过期任务不能重新连接。网络清理不完整时停止重建，保留恢复错误。模式和服务地址在恢复期间不能修改。日志记录恢复开始和成功事件。

连接后立即执行三层检查，之后每约 30 秒再次检查：节点入口 TLS/ECH、经隧道解析域名的有效 A 记录、独立于 DNS 的外部 TLS/HTTP 响应。入口失败、DNS 失败、出网失败分别显示；成功的入口检查不会覆盖其他层的失败。检查目标有限，不能保证任意网站可达。

DNS 在两个 TCP 解析器和两个 HTTPS 解析器之间容错，优先最近成功的通道，单次尝试最多 2 秒、完整查询最多 8 秒，并限制并发。HTTPS DNS 固定引导 IP，正常验证域名和证书，不调用系统代理。请求采用 [RFC 8484](https://www.rfc-editor.org/rfc/rfc8484.html) 的二进制 DNS POST，Google 路径依照[官方说明](https://developers.google.com/speed/public-dns/docs/doh/)。所有通道经现有 H2 隧道。

IPv6 使用原子状态保证并发读写安全。每个检查周期重新探测两个 IPv6 出口目标；失败时立即切到 IPv4，恢复需连续两次成功，切换后刷新系统 DNS 缓存。DNS 过滤策略即时读取新状态。

- `tun-product-acceptance-v0.6.13.json`：15 项实际发布 EXE 验收，包含真实默认路由/DNS、Google 首页、1 MiB 下载、三个健康检查、守护进程暂停 17 秒后的自动重建、重建后 Google 访问、第二次恢复中取消并验证不再连接、断开重连和网络清理。使用隔离 beta 账号，原 Windows 系统代理值保持一致。

- `TestLiveNetworkHealthAndDoH`：真实隔离 beta 节点，两家 DoH、DNS 检查及 HTTPS 出网检查通过。
- Go 故障模拟覆盖 DNS 通道失败/恢复、错误响应 ID 拒绝、IPv6 失效与两次成功恢复、健康层独立状态、取消/断开/注销后的过期重连拒绝，以及旧守护任务不影响新会话。
- Go 全量测试、vet 与桌面模块测试通过。首次并行测试遇到 Windows 临时目录清理失败，相关包重跑及后续串行全量运行均通过。
- UI 交互回归 67 项、运行时回归 8 项、真实 Wails 绑定 20 项通过。未启动 GUI 做视觉验收。
- 常规客户端真实 EXE 验收及后台发布结果另见对应版本的 `admin-desktop-acceptance`、`admin-alignment-deployment`、`unified-release` 报告。

## 范围与限制

实际物理网卡切换、整机睡眠以及其他 VPN 共存没有进行硬件实测；上述恢复测试通过受控暂停与出口指纹注入覆盖生产恢复路径。短于 15 秒且出口未变的暂停不会仅因时间间隔重建。IPv6 部分目标不可达仍可能存在，两个探测地址不能代表整个互联网。

重建会中断已有连接；应用需自行重试。清理至重建期间系统恢复原路由，本版没有 kill switch。没有承诺下载任务或游戏会话可以无缝续接，也没有进行长时间吞吐量测试。

主站、beta 和公开 EXE 使用同一产品版本；原节点核心、原服务 PID、支付配置与节点制品保持不变。已运行的旧客户端不会自动替换。
