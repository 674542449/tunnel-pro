# v0.5.5 用户购物与管理员全流程验收

验收日期：2026-10-03（北京时间）。本轮从新访客、新用户和管理员入口出发，操作真实 HTTP 接口和页面 DOM，修复发现的问题后重新执行全套回归。

## 用户操作

14 组旅程通过：访客目录、邀请注册、邮箱验证与购买门槛、取消订单、模拟付款与到账、连续续费、流量加购、账单、退款展示、工单提交/回复/关闭/重开、退出、跨账号隔离、密码找回链接。用户测试加载编译后实际提供的 JavaScript，并检查运行时异常。

修复：

- 未登录用户打开找回密码链接，初始化 `/me` 的 401 响应会关闭重置弹窗，同时链接令牌已从地址栏移除。现在先完成初始身份检查，再处理安全链接。
- 页面已经打开时，同页跳转到找回、验证或邀请链接没有处理。现在监听相应地址片段变化。
- 订单每 15 秒自动刷新会打断搜索输入。输入框、文本域或选择框获得焦点时暂停刷新。
- 搜索旧套餐后创建其他套餐订单，旧筛选条件会隐藏新订单与付款按钮。创建成功后清空订单搜索条件。
- 购买周期套餐和流量包，退款周期套餐后再购买，旧流量包会把新周期推迟开通。续费排队现在只计算周期权益。
- 已创建过收银台的流量包绕过再次购买条件检查。现在复用收银台之前也会检查基础周期和节点快照。

## 管理员操作

9 组旅程通过，覆盖 13 个页面：节点手动添加、安装令牌错误/重发/旧令牌拒绝/安装完成、节点编辑启停、套餐范围和金额、上下架删除、订单快照和取消、退款、用户角色和会话撤销、客服财务权限、封禁恢复、后台重启后状态保留。

修复：

- 模拟付款模式下，手动新建节点可能成为正式节点。表单补齐使用范围，后端强制隔离测试模式，编辑时保留原范围。
- 节点仍被套餐、未到期待付订单或未结束权益引用时可被删除。现在拒绝删除并给出处理提示；解除引用和处理权益后可以删除。
- 旧订单的节点快照丢失时仍可能发起收款。下单、发起支付和发放权益均检查节点引用；真实迟到付款保留为“已付款待处理”，仍能退款。迟到付款告警也不再错误声称已发放权益。
- 自助改密或管理员重置密码后，旧找回链接仍可使用；已有未完成的 MFA 绑定请求也仍有效。三种密码替换路径现在一并失效旧恢复链接和未完成绑定请求，并撤销会话。已正式启用的 MFA 保留。

## 验证结果

- 真实接口与 DOM：用户旅程 14 组、管理员旅程 9 组、原后台 23 项、商业流程 21 项、MFA 8 项，合计 75 项通过。
- 新增 Go 旅程测试 7 条，另含三家支付提供商、三种改密路径的子测试，覆盖节点删除保护、到账无法履约、续费退款、额度耗尽与加购、重启后租约预留等。
- 全项目 `go test -p=1 -tags=http2legacy ./... -count=1 -timeout=180s` 和 `go vet -tags=http2legacy ./...` 通过。并行测试曾出现一次 Windows 临时目录清理错误，功能断言未失败；串行完整重跑通过。
- 服务器 ARM64 执行商业、购物、支付和存储测试；PostgreSQL 用例在独立临时 schema 中验证五种支付选项、回调验签/金额/幂等、退款、并发写入、重启与加密备份恢复，完成后清理 schema。其余 Go 旅程使用各自隔离文件存储。
- 线上正式库和试运营库只读检查：套餐、待付订单、有效或排队权益没有悬空节点引用，没有重复购买权益，也没有待处理到账订单。
- Windows amd64、Linux arm64、Linux amd64 网站控制器构建成功。

## 上线记录与范围
